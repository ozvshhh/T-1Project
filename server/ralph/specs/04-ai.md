# 명세 04 — AI 호출 모듈 C2 (단계 4)

바탕: `docs/api.md` 0절(스트리밍 없음, JSON 한 번)·1절(`502 AI_UNAVAILABLE`, 저장 안 함), C2, 03-delivery(키는 `AI_GATEWAY_API_KEY`만, 비어도 기동, 팀 예산 $10).
참고 구현: `interview-engine/src/llm.ts`(같은 Gateway·OpenAI 호환 호출, zod 검증). 복사해 와도 되지만 `server/src/ai/` 안에서 완결한다(interview-engine은 보류 기능이라 import하지 않는다).

## 결정
- `AiService.json<T>({ task, system, user, schema })`: Vercel AI Gateway OpenAI 호환 `POST {AI_GATEWAY_BASE_URL}/chat/completions`(기본 `https://ai-gateway.vercel.sh/v1`), `response_format` JSON 스키마, 응답을 zod로 검증해 `T`를 돌려준다.
- 모델 `AI_MODEL`(기본 `openai/gpt-6.1-terra`, 팀 결정 2026-10-29 interview-engine README). 타임아웃 `AI_TIMEOUT_MS`(기본 30000). 재시도는 네트워크·5xx·형식 오류에 한해 1회. 숫자·이름은 `server/src/ai/ai.config.ts` 한 곳에.
- 키는 `process.env.AI_GATEWAY_API_KEY`에서만 읽는다. 비었으면 네트워크 호출 없이 바로 `AiUnavailableError`.
- 모든 실패(키 없음, 401/402/429/5xx, 타임아웃, JSON·스키마 불일치)는 `AiUnavailableError` 하나로 모으고, 전역 필터가 `502 {error:{code:"AI_UNAVAILABLE", message}}`로 바꾼다. message에 키·원문 응답·스택을 넣지 않는다.
- 호출마다 `task` 이름·모델·입출력 토큰 수·걸린 시간만 로그 한 줄(내용·키 없음). 예산 추적용.
- **테스트는 실제 Gateway를 절대 부르지 않는다.** `test/fake-ai.ts`(또는 `src/ai/fake-ai.service.ts`)의 `FakeAiService`가 task별로 미리 넣은 응답·실패를 돌려준다. 이후 모든 e2e 테스트는 `AiService`를 이것으로 바꿔 끼운다. `AiService` 단위 테스트는 `fetch`를 가짜로 바꿔 검사한다.
- 「저장 안 함」 원칙(C2)은 각 기능이 지킨다: AI 호출을 먼저 끝낸 뒤에만 DB에 쓴다. 이 단계는 그 순서를 강제하는 공통 도우미가 필요하면 만든다(선택).

## 완료 기준 (주장)
- [ ] C4-1: `AiService.json`이 가짜 `fetch`에 대해 올바른 URL·`Authorization: Bearer <키>`·`model`·`response_format`을 보내고, 정상 응답을 zod 검증한 객체로 돌려준다. 키가 비면 `fetch`를 부르지 않고 `AiUnavailableError`. 단위 테스트 있음.
- [ ] C4-2: 401·429·500 응답, 타임아웃, JSON이 아닌 응답, 스키마 불일치가 모두 `AiUnavailableError`가 되고, 5xx·형식 오류는 정확히 1회 재시도한다(호출 횟수 단언). 예외가 HTTP로 나가면 `502 AI_UNAVAILABLE`이고 본문에 키·원문 응답·스택이 없다(테스트).
- [ ] C4-3: `FakeAiService`가 있고 task별 응답 큐·실패 주입·받은 입력(system/user) 기록을 지원한다. 저장소 전체 테스트에서 실제 네트워크 호출이 없음을 보장하는 장치(예: jest setup에서 전역 `fetch`를 호출 시 실패하는 가짜로 교체)가 있다. 호출 로그 한 줄에 task·model·토큰 수·시간이 있고 키·내용은 없다(테스트).
