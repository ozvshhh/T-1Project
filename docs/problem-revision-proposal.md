# 문제 정의 수정안 (팀 합의 전 — problem.yaml은 아직 바꾸지 않음)

2026-10-29, 팀원(a77315829-byte 세션)이 낸 수정안이다. **팀이 합의하기 전에는 `docs/problem.yaml`을 고치지 않는다.**
비교 기준은 main의 최신 `docs/problem.yaml`(ddb52d2, PR #5까지 반영)이다.

## 왜 수정안을 냈나

- 이 세션에서 해결 흐름을 정했다: 이력서 입력 → 자소서 초안 생성 또는 기존 자소서 등록 → 실무·임원 모의면접 → 설명이 부족한 부분 확인 → 자소서 보완. 자세한 설계는 `docs/interview-design.md`.
- 안내서는 기능이 문제 정의에서 고른 해법과 이어져야 한다고 한다. 그래서 이번에 풀 어려움을 이 흐름에 맞게 구체화하자는 것이다.
- 팀이 이미 확정한 방향(면접 쪽, 처음 구직하는 취준생)은 그대로 둔다.

## 칸별 비교

### customer (고객)

- **지금 (main):** 1차 고객 구직자 — 처음 구직하는 취준생. 4학년 2학기, 프로젝트·해커톤·동아리·대외활동은 했지만 기록이 없어 말 말고는 증명할 수 없는 사람. 서류는 붙는데 면접에서 떨어지거나, 경험은 많은데 직무에 맞게 어필할 줄 모르는 사람. 2차(보조) 회사.
- **수정안:** 취업 준비를 처음 시작해 자신의 경험을 자소서와 면접 답변으로 정리하는 데 어려움을 겪는 대학 4학년·첫 취업 준비생.
- **차이:** 수정안은 "핵심 고객은 그대로"라고 했다. 대상은 같고 표현만 다르다. 2차(보조) 고객인 회사를 남길지는 수정안에 없다.

### statement (한 문장 문제 정의)

- **지금 (main, 팀 확정 2026-10-29):** 정량적 스펙 중심으로 준비해 온 취준생이 자신의 구체적인 기여도와 문제 해결 역량을 논리적으로 설명하지 못해, 서류 작성을 어려워하고 실전 압박 면접에서 무너지는 문제
- **수정안:** 첫 취업 준비생은 자신의 경험을 지원 직무와 연결해 자소서로 정리하고, 그 내용을 면접에서 구체적으로 설명하는 데 어려움을 겪는다. 초안을 작성한 뒤에도 본인의 역할·선택 이유·결과를 충분히 설명했는지 확인하기 어렵다.
- **차이:**
  - 수정안에 새로 들어간 것: "지원 직무와 연결", "초안을 쓴 뒤에도 역할·선택 이유·결과를 충분히 설명했는지 확인하기 어렵다".
  - 수정안에서 빠진 것: "정량적 스펙 중심으로 준비해 온", "실전 압박 면접에서 무너지는".
  - 자소서와 면접 둘 다 다룬다는 점, 기여도·역할을 설명하지 못한다는 점은 같다.

## 합의할 때 같이 볼 것

- **면접관 수와 압박 여부:** progress.md의 2-B 해법 메모(팀원)에는 차별점으로 "삼인 삼색 보이스 페르소나, 꼬리질문 압박 인터렉션"이 적혀 있다. 이번 설계는 면접관 2명(실무·임원)이고, "기억이 안 난다는 답변을 계속 추궁하지 않는다"는 규칙이 있다. 지금 statement의 "실전 압박 면접에서 무너지는"과도 연결된다.
- **근거:** 수정안의 "초안을 쓴 뒤에도 충분히 설명했는지 확인하기 어렵다"를 뒷받침하는 experiences는 아직 없다. 지금 있는 E1(꼬리질문에 막힘), E2(자소서 문항에서 막힘)와 어떻게 이어지는지 팀이 확인해야 한다.
- 합의 뒤에는 solution_paths(고른 해법)와 features(기능 명세)를 `docs/interview-design.md`에서 옮긴다.
