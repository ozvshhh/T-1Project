# 화면 명세서 (초안)

프론트엔드 랄프 루프가 읽는 화면 명세다. 기능·흐름은 팀이 정한 `docs/problem.yaml`(F1~F9)과 `docs/scenarios.yaml`(S1~S6)을, 서버 호출은 `docs/api.md`를, 시각은 `docs/design/DESIGN.md`를 따른다. 이 문서는 그것들을 **화면 단위로 옮긴 것**이고 새 기능을 더하지 않는다.

표시 규칙
- **[확정]** 팀 문서에 있는 내용. **[제안]** 문서에 없어서 임시로 정한 것(경로, 배치 등). 바꿔도 되지만 바꾸면 `docs/scenarios.yaml`과 E2E를 같은 commit에서 고친다.
- **[학생 답 대기]** 팀이 아직 정하지 않은 제품 결정. 랄프 루프는 짐작해서 채우지 말고 `progress.md`에 적고 멈춘다.

## 0. 공통

**기준 화면** [확정]: 데스크톱(PC 브라우저, 넓은 화면). 모바일은 만들지 않는다.

**화면 이름(메뉴·버튼 글자)은 시나리오와 글자 하나까지 같아야 한다** [확정]. E2E가 이 글자로 찾는다. 아래 따옴표 안의 글자를 그대로 쓴다.

**상단 메뉴** (로그인 후 모든 화면) [확정]
- 왼쪽부터: '내 이력서' · '내 자기소개서' · '모의면접' · '면접 기록'
- 오른쪽: 로그인한 이메일 + '로그아웃' [제안: 로그아웃 위치]

**경로** [제안]

| 화면 | 경로 |
| --- | --- |
| 첫 화면 | `/` |
| 회원가입 / 로그인 | `/signup` / `/login` |
| 내 이력서 | `/resume` |
| 내 자기소개서 목록 / 등록 / 상세 | `/cover-letters` / `/cover-letters/new` / `/cover-letters/:id` |
| 모의면접 시작 | `/interview` |
| 모의면접 진행 | `/interviews/:id` |
| 면접 결과 | `/interviews/:id/result` |
| 면접 기록 | `/interviews` |
| 없는 주소 | `*` (404 화면, 상태 코드는 서버가 404) |

**인증** [확정]: 로그인 전에는 로그인 필요 화면이 열리지 않는다(`/login`으로 보냄, 가입·로그인 직후 원래 가려던 곳으로). `/`는 로그인 안 한 사람에게 서비스 이름과 하는 일을 보여 주고, 로그인 칸만 두지 않는다. 세션은 `HttpOnly` 쿠키라 프론트는 토큰을 저장하지 않는다. `GET /api/auth/me`로 로그인 여부를 확인한다.

**API 호출** [확정]: 모든 주소는 상대 경로(`/api/...`). `localhost:3000` 같은 절대 주소를 쓰지 않는다. 오류 응답은 `{ error: { code, message } }`이고 `message`를 그대로 보여 줘도 된다.

**공통 상태** 모든 화면은 아래 셋을 가진다 [제안]
- 불러오는 중: 영역 안에 '불러오는 중' 글자(스피너만 두지 않는다)
- 비어 있음: 무엇을 하면 채워지는지 한 줄 안내 + 이동 버튼
- 실패: 오류 `message`와 '다시 시도' 버튼

**시각** [제안, `DESIGN.md` 기준]: 흰 바탕·검정 글자·알약(pill) 버튼이 뼈대. 색 블록은 단계 구분에만 쓴다 — 이력서(연두) → 자기소개서(연보라) → 모의면접(크림), 마지막 행동(예: '면접 시작')만 코랄. 폰트는 Wanted Sans + Inter, 크고 가벼운(400) 제목. 컨테이너 최대 1280px.

## 1. 첫 화면 `/` (로그인 전)

- 목적: 서비스가 무엇을 하는지 알려 주고 가입으로 보낸다. [확정: 서비스 이름·하는 일이 보여야 함]
- 구성: 서비스 이름, 하는 일 설명, 3단계(이력서 → 자기소개서 → 음성 모의면접) 소개, '회원가입', '로그인' 버튼.
- 서비스 이름과 설명 문구: **[학생 답 대기]** (첫 화면에서 알려 줄 것을 학생과 정하는 항목). 확정 전에는 'T-1Project'를 임시 이름으로 쓴다.
- 로그인한 사람이 `/`를 열면 '내 이력서'로 보낸다. [제안]
- 완료 조건: 로그아웃 상태에서 서비스 이름과 두 버튼이 보인다.

## 2. 회원가입 `/signup` · 로그인 `/login` (F1, S1)

- 입력: 이메일, 비밀번호(8자 이상). 버튼: '가입하기' / '로그인'. 서로 이동하는 링크 한 줄. [확정: 이메일·비밀번호, '가입하기']
- API: `POST /api/auth/signup`, `POST /api/auth/login`.
- 성공: 가입 즉시 로그인되어 **'내 이력서' 화면이 열리고 위쪽에 가입한 이메일이 보인다**. [확정: S1 expected]
- 실패 표시: 이메일 중복(`EMAIL_TAKEN`), 잘못된 로그인(`INVALID_CREDENTIALS`), 형식 오류(`VALIDATION`)는 입력칸 아래에 `message`로 보이고 입력값은 유지한다. [제안]
- 시드 계정으로 아이디·비밀번호만 입력해 바로 로그인된다. [확정]

## 3. 내 이력서 `/resume` (F2, S2)

- 목적: 9개 항목 중 골라서 경험을 쓴다. 저장하면 내 이력서가 된다. 사용자당 1개. [확정]
- 구성
  - '항목 고르기': 9개 체크박스. 이름은 1분 자기소개 / 직무 관련 성공경험 / 직무를 위해 준비한 사항 / 지원동기 / 입사 후 포부 / 성격의 장단점 / 위기 극복 경험 / 성장과정 / 팀워크 및 협업경험. [확정]
  - 체크한 항목마다 글 입력칸이 생긴다. 칸 이름은 항목 이름과 같다. 체크를 풀면 칸이 사라진다. [확정]
  - '저장' 버튼. [확정]
- API: `GET /api/resume/template`, `GET /api/resume`, `PUT /api/resume`.
- 저장 성공: '저장 완료' 표시가 보인다. 새로고침해도 고른 항목과 내용이 그대로다. 저장 뒤 내용 수정·항목 추가가 된다. [확정]
- 검증: 항목을 하나도 안 고르거나 칸을 비운 채 저장하면 경고가 보이고 저장되지 않으며 다시 입력하게 된다. [확정]
- 저장된 이력서가 있으면 그 상태로 열린다. 이력서가 없을 때(처음)는 모든 체크가 꺼진 상태. [제안]
- 이력서 아래에 '내 자기소개서'로 가는 안내 버튼(연보라). [제안]

## 4. 내 자기소개서 `/cover-letters` (F3, F4, S3, S4)

### 4-1 목록
- 최신순 목록: 제목, 만든 방식(생성/등록), 만든 날짜. 클릭하면 상세. 자기소개서는 여러 개 둘 수 있다. [확정]
- 버튼: '이력서로 초안 만들기', '자기소개서 등록'. [확정]
- 비어 있을 때: "아직 자기소개서가 없어요. 이력서로 초안을 만들거나 이미 쓴 글을 등록하세요." [제안]
- API: `GET /api/cover-letters`.

### 4-2 초안 만들기 (S3)
- '이력서로 초안 만들기' → `POST /api/cover-letters/generate`. 저장된 이력서가 바탕이다.
- 진행 중: 버튼 비활성 + "초안을 만들고 있어요" 표시. 시간이 걸릴 수 있다(AI 호출). [제안]
- 성공: 초안 본문이 화면에 보이고 목록에 새 항목이 하나 늘어난다. [확정]
- 실패(`AI_UNAVAILABLE`): 에러 안내가 보이고 목록은 늘지 않는다. [확정]
- 이력서가 없거나 항목이 없으면(`VALIDATION`) '내 이력서'를 먼저 채우라는 안내와 이동 버튼. [제안]
- 초안을 사용자가 고칠 수 있는지, 문항별인지 한 덩어리인지: **[학생 답 대기]** (정해지기 전에는 읽기 전용 한 덩어리로 보여 준다)

### 4-3 등록 `/cover-letters/new` (S4)
- '자기소개서 등록' → 본문 칸(큰 입력창), 제목은 선택 입력. 버튼 '저장'. [확정: 본문 칸·'저장']
- 성공: 목록에 보이고, 열면 입력한 본문이 그대로다. [확정]
- 본문이 비었거나 공백만이면 저장되지 않고 이유가 보인다. [확정]
- API: `POST /api/cover-letters`.

### 4-4 상세 `/cover-letters/:id`
- 제목, 만든 방식, 본문 전체(줄바꿈 유지). 하단 '이 자기소개서로 면접 보기' → `/interview`에서 선택된 상태로 이동. [제안]
- API: `GET /api/cover-letters/:id`. 없는 id는 404 화면.
- 삭제 기능은 **[학생 답 대기]** → 넣지 않는다.

## 5. 모의면접 시작 `/interview` (F5, S5)

- 자기소개서 목록에서 하나 고르고 '면접 시작'을 누른다. [확정]
- 자기소개서가 없으면 '내 자기소개서'로 보내는 안내. [제안]
- 안내 문구: 면접관 2명(실무·임원), 질문은 글자로 보이고 소리로도 읽어 준다, 마이크가 없으면 글자로 답할 수 있다. [제안]
- 시작 중: "질문을 준비하고 있어요" (목표 10초 이내). 실패해도 기본 질문으로 진행되므로 오류로 막지 않는다. [확정]
- API: `POST /api/interviews` → 응답의 `interview.id`로 `/interviews/:id`로 이동.

## 6. 모의면접 진행 `/interviews/:id` (F5, F6, F7, F9, S5)

**레이아웃** [제안, 넓은 화면 기준]: 왼쪽 큰 영역에 면접관·질문, 오른쪽에 내 카메라와 답변 영역.

- **면접관·질문 영역** [확정: 이름과 질문이 글자로 보임]
  - '실무 면접관' 또는 '임원 면접관' 이름, 질문 문장(글자). 질문 종류(본질문/꼬리질문)는 작은 표시.
  - 질문이 나오면 소리로 읽어 준다(`GET /api/speech/tts`). 실패하거나 소리가 없어도 글자는 항상 보이고 진행된다. '질문 다시 듣기' 버튼은 질문 수에 넣지 않는다.
  - 진행 상황: 질문 번호(예: 3 / 최대 12), 남은 시간(최대 12분). [제안]
- **내 카메라** (F9) [확정]: `getUserMedia`로 미리보기만 보여 준다(저장·전송 없음). 권한 거부·장치 없음·테스트 브라우저에서는 **검은 화면**이 보이고 면접은 그대로 진행된다.
- **답변 영역** [확정]
  - 기본은 음성: 녹음 → 전사(`POST /api/speech/transcribe`) → 전사 내용이 입력칸에 채워지고 **사용자가 확인·수정**한 뒤 제출한다. 전사 결과가 비면(`EMPTY_TRANSCRIPT`) "다시 말해 주세요" 안내.
  - '글자로 답하기'를 누르면 답변 칸(글 입력)이 열린다. 음성과 글자는 같은 '답변 제출'로 간다.
  - 버튼: '답변 제출', '건너뛰기', '면접 종료'.
- **동작**
  - '답변 제출' → `POST /api/interviews/:id/answers` → 다음 질문(꼬리질문 또는 다음 본질문)이 글자로 보인다. 처리 중에는 버튼 비활성 + "다음 질문을 준비하고 있어요". [확정: 다음 질문이 보임]
  - 답변에 점수나 평가를 보여 주지 않는다. [확정]
  - '건너뛰기' → `POST /api/interviews/:id/skip` → 다음 본질문. [확정]
  - '면접 종료' → `POST /api/interviews/:id/end` → 결과 화면으로 이동. 어느 질문에서든 가능. [확정]
  - 한도(전체 12개·12분)에 닿으면 현재 답변을 마친 뒤 자동으로 결과 화면으로 이동. [확정]
  - 새로고침해도 같은 질문·같은 순서(`GET /api/interviews/:id`). [확정]
  - 이미 끝난 면접(`INTERVIEW_FINISHED`)을 열면 결과 화면으로 보낸다. [제안]
- **답변 제출 중 AI 판단 실패 시의 동작**: **[학생 답 대기]**. 정해지기 전에는 오류 안내와 '다시 시도' 버튼을 보여 주고 입력한 답변은 유지한다. [제안: 임시]
- 질문·답변 기록(지금까지)을 접었다 펼칠 수 있게 둔다. [제안]
- 기록 한 줄의 완료 조건: 글자로 답하면 기록에 방금 답이 면접관 이름과 함께 추가된다. [확정]

## 7. 면접 결과 `/interviews/:id/result` (F7, F8, S5, S6)

- **종합 점수는 어디에도 보이지 않는다.** [확정]
- 위에서 아래로 네 구역 [확정]
  1. **질문·답변 기록**: 질문마다 면접관 이름, 질문 목적, 질문, 내 답변(건너뛴 질문은 '건너뜀'). 종료 사유 표시: '사용자 종료' / '질문 한도' / '시간 한도' / '모두 완료'. (S5: 종료 사유가 '사용자 종료'로 보여야 함)
  2. **구체화된 경험**: 역할·선택 이유·결과 중 새로 설명한 내용.
  3. **아직 보완할 항목**: 최대 3개, 각 항목에서 해당 답변으로 이동할 수 있게 연결.
  4. **자기소개서 수정 제안** (제목 그대로 '자기소개서 수정 제안'): 제안마다 원래 문장, 바꿀 문장, 이유, '승인'·'거절' 버튼, 상태 표시(대기/반영됨/거절됨).
- 승인: 상태가 **'반영됨'**으로 바뀌고 `POST .../suggestions/:sid/accept` 응답의 바뀐 본문이 반영된다. 이후 '내 자기소개서'에서 열면 제안대로 바뀐 문장이 들어 있다. 원문이 이미 바뀌어 반영할 수 없으면(`409`) 안내를 보인다. [확정]
- 거절: 상태만 '거절됨', 본문은 그대로. [확정]
- 결과 일부 생성 실패(`resultStatus: "partial"`): 기록(1)만 보이고 나머지 구역은 "결과 분석을 만들지 못했어요" 안내. [확정: 결과 화면은 열림]
- 면접이 아직 진행 중이면(`409`) 진행 화면으로 보낸다. [제안]
- 결과가 만들어지는 동안은 "결과를 정리하고 있어요". [제안]

- 비어 있을 때: '모의면접'으로 가는 안내. [제안]

## 9. 없는 주소 `*`

- "페이지를 찾을 수 없어요" + '홈으로'. 500이 아니라 404 응답이어야 하고, `/api/*`와 `/__health`는 프론트가 가로채지 않는다. [확정]

## 10. 시드 데이터로 돌아가는 화면 (E2E가 기대하는 것) [확정]

기동 시 서버가 만든 데이터만으로 아래가 보여야 한다: 취준생 계정 1개, 이력서 1개(`직무 관련 성공경험`·`팀워크 및 협업경험`), 자기소개서 '시드 자기소개서', 끝난 면접 1개(제안 1개 '대기').

## 11. 흐름 ↔ 화면

| 흐름 | 화면 |
| --- | --- |
| S1 | 첫 화면 → 회원가입 → 내 이력서 |
| S2 | 내 이력서 |
| S3 | 내 자기소개서(초안 만들기) |
| S4 | 내 자기소개서 → 등록 → 목록·상세 |
| S5 | 모의면접 → 진행 → 결과 |
| S6 | 면접 기록 → 결과(수정 제안 승인) → 내 자기소개서 |

## 12. 랄프 루프 작업 순서 제안 (`frontend/fix_plan.md`용) [제안]

1. 공통: 라우터, 인증 가드, 상단 메뉴, 오류·불러오는 중 컴포넌트, API 클라이언트(상대 경로, 오류 형식 처리)
2. 첫 화면 + 회원가입/로그인 (S1)
3. 내 이력서 (S2)
4. 내 자기소개서 목록·등록·상세 (S3, S4)
5. 모의면접 시작·진행(글자 답변, 건너뛰기, 종료) (S5)
6. 면접 결과·면접 기록·수정 제안 승인 (S6)
7. 음성: 녹음·전사 확인·TTS 재생·카메라 미리보기 (F6, F9) — 테스트 브라우저에 마이크·카메라가 없어도 글자 경로가 막히지 않을 것
8. 404, 빈 상태·오류 상태 다듬기, 화면 이름이 `docs/scenarios.yaml`과 같은지 대조

백엔드가 아직 없으면 4~6은 `docs/api.md`의 응답 형태를 따르는 목(mock) 서버로 개발하되, 실제 연결 전에 mock을 걷어낸다(채점 E2E는 실제 서버로만 돈다).
