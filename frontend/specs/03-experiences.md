# 03 경험 목록·경험 등록 (D, E)

근거: R2, R6, screen-spec.md 3절 D·E, api.md 4절. 시나리오: S2, S4.

## D 경험 목록 `/experiences`

- lime 블록. 주 버튼 `경험 추가`(→ `/experiences/new`).
- 목록: `GET /api/experiences`(최근 수정순). 행마다:
  - 제목, 시기
  - 다섯 항목 칸 `상황`·`역할`·`행동`·`결과`·`의의`: 그 항목에 확정 사실이 있으면 흰 칸, 없으면 점선 칸
  - 확인 대기 후보가 있으면 `확인 대기 N`
  - 행(제목)을 누르면 `/experiences/:id`.
- 비어 있으면 점선 행 `아직 경험이 없어요`.

## E 경험 등록 `/experiences/new`

| 영역 | 화면 글자 |
| --- | --- |
| 필수 입력칸 | `제목`, `대략적 시기`(자리표시자 `예: 2025년 여름`) |
| 단서(선택) | 보조 버튼 `파일 추가`, `글로 추가` |
| 파일 단서 한 개 | 선택 `종류`(`사진`/`수상기록`/`문서`), 파일 선택, 입력칸 `설명`, 버튼 `빼기` |
| 글 단서 한 개 | 입력칸 `단서 내용`, 버튼 `빼기` |
| 주 버튼 | `대화 시작` (단서가 없어도 누를 수 있다) |

- `설명` 칸 아래 안내: `설명을 쓰지 않은 파일은 보관만 되고 AI 질문에는 쓰이지 않아요.`
- 동작: `POST /api/experiences` → 단서마다 `POST /api/experiences/:id/clues`(파일은 multipart, 글은 JSON `type: text`) → `/experiences/:id`.
- 예외:
  - `제목`·`대략적 시기`가 비면 저장하지 않고 칸 아래 `필수 입력이에요.`
  - 단서 업로드 하나가 실패해도 경험은 이미 만들어졌으므로 `/experiences/:id`로 가고, F 화면에 `올리지 못한 단서가 있어요. 다시 추가해 주세요.`를 띄운다.

## 테스트

- 단서 없이 `제목`·`대략적 시기`를 넣고 `대화 시작`을 누르면 경험 상세로 간다.
- `제목`을 비우고 누르면 `필수 입력이에요.`가 보이고 이동하지 않는다.
- 경험 목록에 시드 경험 두 개와 항목 채움 칸이 보인다.
