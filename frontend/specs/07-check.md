# 07 제출 전 점검 (K) `/checks/:checkId`

근거: R9~R12, C1, C4, screen-spec.md 3절 K, api.md 9절, 학생 답(2026-10-30: 문장마다 고치기·보강 바로가기). 시나리오: S6. 자소서 잠금 적용.

cream 단계. 데스크톱은 두 칸: 왼쪽 문장 목록, 오른쪽 현재 문장.

## 위

- 진행 막대: 끝난 문장(`explained`·`needs_more`·`unknown`) 수 / 전체. 아래 한 줄 `끝난 문장 N / 전체 M`.
- 점수는 없다(R11).

## 왼쪽: 문장 목록 (R9, R11)

- 제목 `점검할 문장`. 문장마다 글과 상태(00-common.md 상태 표시). 누르면 그 문장을 오른쪽에 연다.
- 문장이 하나도 없으면 `점검할 주장 문장을 찾지 못했어요.`와 보조 버튼 `자소서로 돌아가기`.

## 오른쪽: 현재 문장 (R10)

- 들어올 때 `in_progress` 문장이 없으면 첫 `pending` 문장에 `POST .../sentences/:sentenceId/start`.
- 질문과 답을 줄 단위로 쌓는다(`질문`, `내 답`).
- 답마다 판정: 판정 목록(`judge`)의 기준을 `J1 수치의 출처`, `J2 본인의 행동`, `J3 표현의 실체`, `J4 단정` 이름으로, 결과를 `충족` / `빠짐`으로 보여 준다.
- `남은 추가 질문 N개`(`followUpsLeft`).
- 입력칸 `답변`, 주 버튼 `답하기` → `POST .../sentences/:sentenceId/answers`. 비면 잠근다.
- 문장이 끝나면 상태를 보여 주고 보조 버튼 `다음 문장`(다음 `pending` 문장의 `start`). 서버가 자동으로 넘기지 않는다. 남은 문장이 없으면 `모든 문장을 점검했어요.`

## 끝난 문장이 `추가 확인 필요` 또는 `모름·경험 없음`일 때

- 보조 버튼 `자소서에서 고치기`: 붙여넣음이면 `/cover-letters/:id`, 작성함이면 그 문장의 `coverLetterItemId` 문항 `/cover-letters/:id/items/:itemId`.
- 보조 버튼 `관련 경험 대화 이어가기`: 작성함이면 그 문항의 근거 카드(하나면 바로, 여럿이면 고르는 목록), 붙여넣음이면 전체 경험 목록에서 골라 `/experiences/:id`.
- AI는 문장을 고쳐 주지 않는다(C4).

## 사실 후보 (R12, C1)

- 제목 `카드에 넣을 사실`. 후보마다 내용과 `AI 제안·미확인`.
- 버튼 `카드에 저장`: 펼쳐서 선택 `경험`(후보의 `experienceId`가 있으면 기본값), 선택 `항목`, 출처 라디오 `내가 말함` / `자료로 확인`(+ 선택 `단서`, 고른 경험의 단서), 버튼 `저장` → `POST /api/checks/:checkId/candidates/:factId/confirm`.
- 버튼 `버리기` → `DELETE` 같은 경로.

## 오래된 점검 (`stale: true`)

- 맨 위 띠: `자소서가 바뀌어 이 점검은 더 진행할 수 없어요.`
- `답변`·`답하기`·`다음 문장` 잠금. 주 버튼 `새 점검 시작`(→ `POST /api/cover-letters/:id/checks` → 새 점검). 기록은 그대로 보인다.
- `409 CHECK_STALE`을 받아도 같은 화면으로 바꾼다.

## 테스트

- 시드 자소서 점검: 문장 목록과 첫 질문이 보인다.
- `답변`에 글을 넣고 `답하기` → 답이 기록에 추가되고, 다음 질문 또는 상태 글자가 보인다. 점수는 보이지 않는다.
- `모름·경험 없음`으로 끝난 문장에 `자소서에서 고치기`, `관련 경험 대화 이어가기`가 보인다.
- `stale` 점검이면 안내 띠와 `새 점검 시작`이 보이고 `답하기`가 잠겨 있다.
