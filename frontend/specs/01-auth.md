# 01 소개·가입·로그인 (A, B)

근거: R1, C3, screen-spec.md 3절 A·B, api.md 3절. 시나리오: S1, S2.

## A 소개 `/`

- 구성(위에서 아래로):
  1. 서비스 한 줄: `경험을 대화로 꺼내 사실을 확정하고, 제출 전에 자소서의 주장 문장마다 근거를 물어 설명할 수 있는지 점검해요.`
  2. 흐름 3단계 블록: `1 경험 꺼내기`(lime), `2 자소서 쓰기`(lilac), `3 제출 전 점검`(cream). 블록마다 한 줄 설명.
  3. 코럴 CTA 블록: 주 버튼 `가입하기`(→ `/signup`), 보조 버튼 `로그인`(→ `/login`).
- 지어낸 숫자·후기를 넣지 않는다.

## B 가입 `/signup` · 로그인 `/login`

| 화면   | 입력칸               | 주 버튼    | 다른 화면 링크 |
| ------ | -------------------- | ---------- | -------------- |
| 가입   | `이메일`, `비밀번호` | `가입하기` | `로그인`       |
| 로그인 | `이메일`, `비밀번호` | `로그인`   | `가입하기`     |

- 동작: `POST /api/auth/signup` 또는 `POST /api/auth/login` → 응답의 `token`을 localStorage에 저장 → `/cover-letters`(로그인 전 가려던 주소가 있으면 그곳).
- 예외:
  - `409 EMAIL_TAKEN`: `이미 가입된 이메일이에요.`
  - `401 INVALID_CREDENTIALS`: `이메일 또는 비밀번호가 맞지 않아요.`
  - `400 VALIDATION`: 해당 칸 아래에 `details`의 사유.

## 테스트 (vitest + RTL + MSW)

- 가입 화면에서 `이메일`·`비밀번호`를 넣고 `가입하기`를 누르면 홈으로 가고 토큰이 저장된다.
- 이미 있는 이메일로 가입하면 `이미 가입된 이메일이에요.`가 보인다.
- 로그인 상태로 `/`에 오면 `/cover-letters`로 간다.
